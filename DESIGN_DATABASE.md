# Database Design

The app stores its state in SQLite.
The tables are created on start from `src/lib/server/db/schema.sql`.

Posts themselves are not in the database; they are Markdown files in the [posts repository](./DESIGN_CONTRIBUTE.md#posts-repository).

Changes to the database schema must always be non destructive and preserve the existing data. 

## Conventions

- Tables for [Humans](./DESIGN_HUMANS.md), [Tasks](./DESIGN_TASKS.md) and [Consume](./DESIGN_CONSUME.md) follow the `kejser-code:database` skill:
  - singular table names;
  - `<table>_id` surrogate `BIGINT` keys, generated by the insert statement;
  - the display name of a row is the column named after its table (e.g. `human.human`, `task.task`).
- The integration and publishing tables (`accounts`, `oauth_clients`, `ftp_server`, `git_repo`, `publish_attempts`) keep their own names.
- Timestamps are epoch milliseconds in `BIGINT` columns named `<event>_at`.
- Flags are `0` or `1`.
- Days are `YYYY-MM-DD` text, or `--MM-DD` when the year is unknown; `''` means no day.
- Enumerations are upper-case text with a `CHECK` constraint.

## Humans

| Table                | Holds                                                                                        |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `human`              | Display name (`human`), first and family name, birthday, kudos (0–10), linked Google contact |
| `human_middle_name`  | Middle names, in order                                                                       |
| `human_nickname`     | Nicknames                                                                                    |
| `human_phone`        | Phone numbers with a type, always with the country code (`+` and digits)                     |
| `human_address`      | Addresses with a type and a Google Maps link                                                 |
| `human_special_day`  | Special days with a type                                                                     |
| `human_group`        | Groups of humans                                                                             |
| `human_group_member` | Which humans are in which groups; a human may be in several                                  |

- `human.google_resource_name` links a human to a Google contact; `''` means the human was added by hand.
- Deleting a human deletes their details, group memberships and content sources.

## Consume

| Table            | Holds                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------- |
| `publisher`      | Companies, agents and channels (`publisher_kind`), with their kudos                    |
| `content_source` | The URI of a content source, owned by exactly one human or one publisher, and its feed |
| `article`        | Articles read from a source's feed: heading, summary, full text when available         |

- `content_source.human_id` and `content_source.publisher_id` are nullable; exactly one is set.
- `content_source.feed_uri` is the RSS or Atom feed found for the URI; `''` means none has been found.
- An article is unique per source by the feed's `guid`; re-reading a feed updates it.

## Tasks

| Table  | Holds                                                                |
| ------ | -------------------------------------------------------------------- |
| `task` | Name (`task`), description, urgent and important flags, and due date |

## Integrations and publishing

| Table              | Holds                                                                            |
| ------------------ | -------------------------------------------------------------------------------- |
| `accounts`         | One connected account per integration, with encrypted access/refresh tokens      |
| `oauth_clients`    | The OAuth app (client id, encrypted secret) per integration                      |
| `ftp_server`       | The blog site upload server and the result of its last connection test           |
| `git_repo`         | The posts repository, its commit author and the result of its last sync          |
| `publish_attempts` | Status, error and remote id/url of each post's publish per platform              |
| `app_setting`      | Single settings, such as the name of the Claude API token's environment variable |

## Encryption

- Tokens and client secrets are encrypted with `SOCIAL_SANITY_TOKEN_ENC_KEY`.
- Passwords and API tokens are never stored; the tables hold the name of the environment variable that does.
